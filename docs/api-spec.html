Endpoint 02

기술 사전

Endpoint 03

기술별 채용공고

쿼리 파라미터 limit은 기본 5, 범위 1~50. 공고 탭을 열 때만 호출한다 — 지도 첫 로드에 딸려오면 낭비다.

{ company : "회사명(ats_board.company_name)" title : "공고 제목(job_posting.title)" location : "근무지, 없을 수 있음(job_posting.location)" employmentType : "고용 형태, 없을 수 있음(job_posting.employment_type)" publishedAt : "게시 일시, 없을 수 있음(job_posting.published_at)" applyUrl : "지원 링크, 없을 수 있음(job_posting.apply_url)" }

Endpoint 04

기술 군집과 산업 연결 근거

GET /api/v1/tech/{skill_code}/cluster 프론트 미연결 상세 패널 열 때 (예정)

공고 동시출현으로 만든 군집 안에서 이 기술이 어디에 있는지 알려준다. 선점기술을 판정하는 게 아니라, 사분면이 뽑은 후보를 해석할 근거를 준다. 군집 데이터가 없는 기술이면 응답 본문이 null이다 (HTTP 200).

Endpoint 05

월별 시계열

GET /api/v1/timeseries 프론트 미연결 추이 스파크라인 (예정)

기술별 월간 공고 수와 생태계 활동을 함께 내려준다. 기술 하나가 아니라 기간 안의 모든 기술 × 모든 달이 한 번에 온다. 쿼리 파라미터는 from(기본 2025-12-01)과 to(기본 2026-08-01)이며, to는 미포함이다.

meta

{ from : "요청한 시작 월, 그대로 되돌려줌(계산값)" to : "요청한 종료 월, 미포함 경계(계산값)" }

items[]

{ month : "해당 월 1일, 공고 게시일을 월 단위로 자른 것(vw_monthly_job_skill.metric_month)" skillCode : "기술 코드(skill.skill_code)" skillName : "기술 표시명(skill.skill_name)" postingCount : "그 달 이 기술을 요구한 공고 수(vw_monthly_job_skill.posting_count)" githubIssueCount : "그 달 GitHub 이슈 수, 없으면 0(ecosystem_monthly_github_metrics)" githubPullRequestCount : "그 달 GitHub PR 수, 없으면 0(ecosystem_monthly_github_metrics)" stackoverflowQuestionCount : "그 달 Stack Overflow 질문 수, 없으면 0(ecosystem_monthly_stackoverflow_metrics)" }

덜 찬 달은 0으로 나온다

생태계 조인에 is_partial_period = FALSE 조건이 걸려 있다. 아직 진행 중인 달은 매칭되지 않고 COALESCE로 0이 된다. "활동이 없는 달"과 "아직 안 끝난 달"이 응답에서 같은 값으로 보이므로, 화면에서 마지막 달을 그대로 그리면 급락처럼 읽힌다.

정적 JSON을 대체하는 엔드포인트다

상세 패널의 8개월 추이는 지금도 화면에 보이지만 API가 아니라 frontend/lib/techExtras.json(9084줄)에서 읽는다. 이 엔드포인트를 붙이면 그 파일과 scripts/build_tech_extras.py를 지울 수 있다.

Enum

evidenceLabel 네 가지 상태

/tech/{skill_code}/cluster 응답에만 있다. 내부 라벨을 화면에 그대로 쓰지 않는다. 셋 다 "선점 가치가 있다·없다"가 아니라 "산업적 연결을 설명할 근거가 있는가"에 대한 답이다.

supporting_evidence 산업 연결 근거 있음

여러 기업에서 같은 군집 기술과 함께 등장하고, 군집 소속도 안정적이다. 판정 조건 6개를 모두 통과했다. 현재 15개.

weak_evidence 산업 연결 근거 빈약함

군집에는 들어갔지만 조건 하나 이상에서 걸렸다. 등장 기업이 적거나, 특정 기업 편향이 크거나, 군집 경계에 있다. 현재 5개.

insufficient_evidence 판단할 채용 데이터 부족

공고가 5건 미만이라 군집 분석 자체를 돌리지 않았다. 근거가 약한 게 아니라 판단을 보류한 것이므로 weak과 같은 톤으로 묶으면 안 된다. 현재 14개.

null 배지를 그리지 않음

선점기술 후보가 아니어서 판정 대상이 아니다. 기술 대부분이 여기 해당한다. 부정적인 표시를 붙이면 안 된다.

membershipQuality와 헷갈리지 말 것

membershipQuality는 "군집 안에서 얼마나 중심적인가", evidenceLabel은 "선점 후보로서 산업적 근거가 있는가"다. 서로 다른 축이라 core_member인데 weak_evidence인 경우가 실제로 있다. UI에서 섞으면 안 된다.

Wiring

프론트 연결 현황

백엔드가 내려주는 것과 화면에 보이는 것이 다르다. 아래 둘은 API만 있고 부르는 코드가 없다.

엔드포인트 프론트 함수 부르는 곳 화면
/gapmap getGapMapData 컴포넌트 4곳 보임
/skills getSkillIndex 컴포넌트 2곳 보임
/tech/{code}/postings getTechPostings useTechPostings.js 보임
/tech/{code}/cluster getTechCluster 없음 안 보임
/timeseries 없음 없음 안 보임

/cluster는 lib/api.js에 getTechCluster()까지 있고 부르는 컴포넌트만 없다. /timeseries는 fetch 함수부터 없어서 한 단계 더 뒤에 있다.

Caveats

알고 있어야 할 것

군집 데이터만 자동 갱신되지 않는다

다른 엔드포인트가 쓰는 테이블은 매일 자정 배치가 채운다. 군집 3테이블은 노트북을 손으로 돌려 넣은 것이라 asOfDate가 고정돼 있다. 노트북 입력 CSV 경로가 개인 로컬에 박혀 있어 현재는 재실행도 안 되고, DDL도 저장소에 없다.

배포 전 두 가지를 확인할 것

total_skill_cluster와 candidate_skill_evidence의 max(as_of_date)가 다르면 /cluster의 evidenceLabel이 전부 null로 나온다. 그리고 vw_monthly_job_skill이 RDS에 없으면 /timeseries가 500이 난다. RDS가 사설 IP라 로컬에서 확인이 불가능해 둘 다 미검증 상태다.

지도 기술 수가 사전보다 적다

/gapmap은 GitHub과 Stack Overflow 수집이 양쪽 다 성공한 기술만 내려준다. 한쪽이라도 실패하면 조인에서 빠진다. /skills의 detailed 필드가 그 차이를 나타낸다.

임계값은 응답에 없다

evidence 판정 기준(기업 3곳, 안정성 0.80, 기업 편향 0.70 등)은 분석 노트북 상수라 API에도 프론트에도 없다. 옮겨 적으면 두 곳에서 관리하게 된다. neighborCompanyShare 같은 원값을 그대로 보여주면 임계값 없이도 의미가 전달된다.
